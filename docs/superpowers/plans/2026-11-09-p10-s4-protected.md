## Design gaps and contradictions (for the main session)

No item overrides an answered decision or needs an owner answer before the wave runs. Items 1-3 and 13 are real contradictions or holes; the rest are readings of text the design leaves open. Task 18 Step 2 records the ones that change design text. The main session can veto any of them.

1. **A hand edit that removes a protected user cannot be gated.** The brief lists "a manifest edit that removes a user". Through the tool that edit is `revoke USER` (`manifest.RemoveUser`, gated in `planRevokeUsers`, pinned by Task 15). A hand edit is invisible: `apply` loads only the new manifest, so the user and their `protected:` are gone before anything can compare, and the key is an ordinary `Remove` row, exactly as for a hand-removed `operator: true` user today. The design has no mechanism for this and this plan adds none. The self-lockout guard still applies. The README says so (Task 2 docsDelta).
2. **`IsProtected()` does not replace `u.Operator` in `apply/json.go`.** The design's "Two helpers" list says it does, but its own "JSON and reports" paragraph makes `protected: true` additive next to `operator`. Setting `operator: true` on a protected non-operator's key object would be false, so `jsonKey`/`jsonRewrite` keep `Operator: u.Operator` and gain `Protected` (set only when the user is protected and not an operator, so every existing golden stays byte-identical). The same rule applies to `audit/json.go`.
3. **`GrantCount` and `blockEntry` are not in the design's `FleetWide` list.** `GrantCount` landed with S1 after the design was written, and `blockEntry`'s operator check is the one the design's tombstone section says becomes `FleetWide(U)` after S4. Both move to `FleetWide`, or `validate` would overcount a scoped operator and a blocked scoped operator's warning would be lost.
4. **`critical_reasons` for a protected non-operator.** The design names no value. Reusing `operator_missing` would say "operator" about a user who is not one, the falsehood the design's Wording section removes elsewhere. This plan adds `protected_missing` and `protected_cannot_log_in`, reachable only from a manifest that uses the new field, so no existing consumer sees them. Operators keep their strings, so `report_critical.golden.json` stays byte-identical.
5. **`edit.operators` and `edit.protected`.** "The edit summary carries which is which." `EditSummary.Operators` and JSON `edit.operators` hold fleet-wide operator targets only. `EditSummary.Protected` and an additive `edit.protected` (omitted when empty) hold every other acknowledged target, a scoped operator included, because the design prints those as protected.
6. **The confirmation prompt.** The design gives no text for a protected target. `OPERATOR ci: ` would be false, so a list holding any non-fleet-wide target reads `PROTECTED a, b: ` (the design's "a list mixing the two uses the second form"). `OPERATOR x: ` and `OPERATORS a, b: ` stay byte-identical. The header prints one line per target, so it is not a list: a fleet-wide operator keeps its `OPERATOR:` line in a mixed run.
7. **The D21a refusal keeps a paste-ready command.** The design's text abbreviates `'revoke x --operator'`. Today's refusal goes through `h.command`, and CLAUDE.md requires follow-up hints that carry the run's flags, so the message is `x is an operator: --from-server cannot trim it; remove the user with 'sshepherd revoke x --config CFG --operator', or edit its access by hand`.
8. **`--operator given but no target is an operator; drop the flag` stays byte-identical.** The design says "refused, as today". It remains true, because nothing about a target that is neither flag is misdescribed.
9. **The `--from-server` gate reads two lists.** `--operator` needs a protected target among the users named on the command line, checked before the D1c no-op return (the design: "`--operator` with no protected target is refused"). A missing `--operator` is refused only for a user actually trimmed. So `revoke ci --from-server S` on an already-revoked pair is exit 0 with the note, with or without `--operator`; `revoke alice --from-server S --operator` on an already-revoked pair is exit 3; and `revoke ci alice --from-server S --operator`, with ci's pair a D1c no-op, proceeds, and its header names no protected target because ci is not touched. `accessGate` (Task 11) implements it and `TestRevokeProtectedFromServer` pins all three. The old blanket refusal of `--operator` with `--from-server` went with `revokeUsage`'s rule.
10. **`clearEmptiedOperators` must skip non-operators.** It iterated the gate's result, which held only operators until now. A protected non-operator losing its last key keeps `protected: true` (the design: no key requirement) and must not report `ClearsOperator`. A scoped operator is still cleared, so the loop checks `u.Operator` rather than `FleetWide`.
11. **A group entry never scopes an operator and never warns.** The design says "(a `user:` entry, not a group)" for scoping and is silent on warning a group entry naming an operator. `operator_grant_redundant` says "this access entry adds nothing", which is false for a group entry's other members, so it fires only on `user:` entries.
12. **`import -o FILE --force` drops `protected:`** like `operator:`, `groups:` and every other hand-written fact, because a fresh import regenerates from the ssh config; `warnMemoryLost` names only serial and tombstones. S3b's gap 11 raised the same question and it is still open. No code here.
13. **The `--operator` gate is per target and applies whether or not the user holds a grant.** The design conflicts with itself here: its Semantics bullet says the acknowledgement applies "only where the user's access entries grant it", while **Two helpers, not one** puts `IsProtected()`, which takes no server, in `operatorGate`. This plan builds the second, because `revoke` and `rotate` edit the user's manifest entry, which is not per server. Critical-when-missing and written-first order stay per server, since `DesiredFor` and audit see only granted keys. `TestProtectedTargetRefusedEveryPath` pins the gate for a protected user with no grant, and Task 18 Step 2 records it.
14. **A scoped operator's own `*` stays exempt from `wildcard_root`.** `warnWildcardRoot` keeps reading `c.operators`, not `FleetWide`: D20a's text says "non-operator", and the entry replaces an implicit grant that reached every root account anyway. Its comment, "An operator is fleet-wide by definition", is false after S4, so Task 3 Step 4 rewords it. `TestWildcardRootWarning`'s `an operator does not warn` row (`selector_test.go:197`) already pins the behaviour, and Task 6 adds a mutant that reads `FleetWide`.

## How this plan is cut (read first)

### Why the lanes look the way they do

1. **Three rounds.** The design's row for S4 is A `internal/config` · B `internal/audit` · C `internal/apply`, `editrun.go`, `revoke.go`, `rotate.go`, `internal/reconcile`. B and C both need A's `IsProtected`/`FleetWide` to compile, so A is round 1. B and C own disjoint files but cannot run in parallel: C's `TestE2EProtected` needs `audit` to exit 2 with `(CRITICAL: protected key)`, which B ships, and a lane builds only on earlier rounds. So B is round 2 and C is round 3.
2. **`deadcode ./cmd/sshepherd` is part of `make check`.** Every function round 1 adds is reachable from `Parse`: `fleetWideOperators` and `warnRedundantGrant` through `validateAccess`, `IsProtected` through `validateUsers`, and `FleetWide` through `blockEntry` and `serversRendering` (`DesiredFor` reads the fields `c.protected` and `c.fleetWide` and calls neither helper). The lanes of rounds 2 and 3 add only functions with a caller in the same lane.
3. **Two pre-existing fixtures name an operator redundantly and change in round 1,** because `operator_grant_redundant` lands there: `TestOperatorBlockedPairNoWarning` (an operator with an `@db` entry) and `TestReportKeyIssuesGolden`'s `trustConfig` argument (`internal/audit/trust_test.go:209`). The second is why `internal/audit/trust_test.go` is in lane `schema`'s globs; dropping the unneeded entry keeps `report_key_issues.golden.json` byte-identical. An operator's implicit grant covers it.
4. **`TestSchemaRoundTrip*` reflects over `config.User`,** so the `Protected` sample in `cmd/sshepherd/schema_roundtrip_test.go` lands in round 1 with the field, or `make check` fails.
5. **The audit help footer moves.** `exitCodesAudit` (`cmd/sshepherd/run.go`) is lane `editor`'s, not lane `audit`'s, because it is `cmd`. `TestHelpExamplesAndExitCodes` needs README to carry the footer verbatim, so lane `editor` applies its README docsDelta locally for its own gate (Task 15 Step 5). - A golden is rewritten only with `-update` and then read back line by line before it is accepted. Every `-update` run is followed by `git status --short -- '*testdata*'` (a new golden is untracked, so `git diff --stat` would not show it), which must list only the files the step names.
- **Failing first.** Every test is run and seen failing (build failure or assertion) before the code it tests exists; a test that pins behaviour already present says so in its step, and a build failure caused only by a sibling test does not count as seeing it fail.

Report the table with the hand-back. Do not hand back while a mutant is still running, and do not report a survivor without saying why it is equivalent or which test you added to kill it.
- **A Fuzz target added or changed needs its seed corpus** under `<pkg>/testdata/fuzz/<Target>/` (at most 16 entries of 4 KiB or less per target).
- **Before hand-back:** run `make check` (and `make integration` under the runner's lock when the lane says `needsIntegration`), then `git add -A`, unstage every path outside the lane's globs (`README.md` and `CLAUDE.md` always), and write the patch.

	t.Helper()

	}

func TestIsProtected(t *testing.T) {
	for _, tc := range []struct {
		name string
		u    User
		want bool
	}{
		{"plain", User{}, false},
		{"operator", User{Operator: true}, true},
		{"protected", User{Protected: true}, true},

		t.Run(tc.name, func(t *testing.T) {
			if got := tc.u.IsProtected(); got != tc.want {

`operator: true` makes a user **protected** (below) and grants **every** server implicitly, with no
`access:` entry needed.

- `import --operator-key <key-file>` marks a key's owner as an operator at import time.
- An operator's own `servers: ["*"]` entry replaces the implicit grant, so its `except:` takes
  effect: `servers: ["*"], except: [legacy-1]` keeps the operator's key off `legacy-1`. A group's
  `*` entry does not count. **Before this, an operator's own `except:` was ignored, so a manifest
  that already has one narrows when you upgrade.**
- An operator with an `@tag` or literal entry stays fleet-wide, and the entry warns, kind
  `operator_grant_redundant`: `operator "x": this access entry adds nothing; operator: true still grants every server`.
  To limit an operator's scope, drop `operator: true` and use `protected: true`.

A weak operator key freezes every grant on every server it renders on: apply refuses each one until
`rotate` replaces it. Removals still land.

### Protected users

`protected: true` protects a user's keys **only where its `access:` entries grant them**. It grants
nothing by itself, and a protected user with no keys is valid: it has nothing to protect.

- `audit` renders a missing protected key as **CRITICAL** (exit code 2) on a server it is granted,
  because that is the drift class that threatens your ability to reach the fleet. A protected key
  that is not granted on a server is not missing there.
- `apply` writes protected keys **first** in every rendered file, in `users:` order, then the other
  granted keys in `access:` order.
- `revoke` and `rotate` refuse a protected target until you pass `--operator`, whether or not it holds
  a grant. `revoke --from-server` may trim a protected non-operator with `--operator`; an operator
  stays refused.

The flag lives in the manifest, so only `revoke` and `rotate` can check it. A hand edit that deletes
the user is an ordinary key removal to `apply`, and only the lockout guard stands in its way.

// FleetWide reports whether user holds the operator's implicit grant of every
// server: operator: true with no servers: ["*"] entry of their own. Such an
// entry replaces the implicit grant, which is what makes except: work for an
// operator; the user is then an ordinary grantee and still protected (spec
// S4, D21). A group's "*" entry does not count.
func (c *Config) FleetWide(user string) bool { return c.fleetWide[user] }

// fleetWideOperators is c.operators minus each operator with a "*" user:
// entry. A group entry's empty a.User deletes nothing.
func (c *Config) fleetWideOperators() map[string]bool {
	out := make(map[string]bool, len(c.operators))
	for _, name := range c.operators {
		out[name] = true
	}
	for _, a := range c.Access {
		if slices.Contains(a.Servers, "*") {
			delete(out, a.User)
		}
	}
	return out
}

// warnRedundantGrant records that a user: entry cannot narrow a fleet-wide
// operator: an @tag or literal entry adds nothing (spec S4). A group entry
// never warns: it still grants its other members.
func (c *Config) warnRedundantGrant(a Access) {
	if !c.fleetWide[a.User] {
		return
	}
	c.warn(ManifestWarning{Kind: WarnOperatorGrantRedundant, User: a.User, Message: fmt.Sprintf(
		"operator %q: this access entry adds nothing; operator: true still grants every server", a.User)})
}

// (users order; a fleet-wide operator everywhere, any other protected user
// only where granted), then the keys of every other granted user (access
// order). Deterministic; a user is never emitted twice. An operator's own

func (c *Config) DesiredFor(serverName string) []authkeys.Key {
	var keys []authkeys.Key
	first := make(map[string]bool, len(c.protected))
	for _, name := range c.protected {

		if !first[userName] { // redundant grant for a protected user: already emitted
			keys = append(keys, c.keysByUser[userName]...)
		}
	}
	return keys
}

func operatorGate(cfg *config.Config, users []string, acknowledged bool) ([]string, error) {

// protectedTargets lists the users that are protected, target order, once
// each.
func protectedTargets(cfg *config.Config, users []string) []string {
	var gated []string
	for _, name := range users {
		for _, u := range cfg.Users {
			if u.Name == name && u.IsProtected() && !slices.Contains(gated, name) {
				gated = append(gated, name)
			}
		}
	}
	return gated
}

// gateRefusal words the missing acknowledgement. "fleet-wide" is kept only
// while it is true of every name: a list mixing a fleet-wide operator with
// anyone else uses the protected form (spec S4).
func gateRefusal(cfg *config.Config, gated []string) error {
	names := strings.Join(gated, ", ")
	fleetWide := !slices.ContainsFunc(gated, func(n string) bool { return !cfg.FleetWide(n) })
	switch {
	case fleetWide && len(gated) == 1:
		return fmt.Errorf("%s is an operator (fleet-wide, protected); pass --operator to confirm", names)
	case fleetWide:
		return fmt.Errorf("%s are operators (fleet-wide, protected); pass --operator to confirm", names)
	case len(gated) == 1:
		return fmt.Errorf("%s is protected; pass --operator to confirm", names)
	}
	return fmt.Errorf("%s are protected; pass --operator to confirm", names)
}
