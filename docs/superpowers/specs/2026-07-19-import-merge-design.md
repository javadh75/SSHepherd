## Context & goal

`import` is generate-only: re-running it after one host lands in
`~/.ssh/config.d/` produces a whole new draft the operator reconciles by hand —
exactly the toil this project exists to remove. Slice 1 built the hard,
reusable part (comment-preserving append via `internal/manifest`) against
adopt, which needed zero semantic work. This slice adds the semantics import
needs: reconciling freshly-converted hosts and identity-derived users against
an existing, hand-maintained manifest, appending only what is genuinely new,
and resolving conflicts loudly in the manifest's favor.

## Decisions (locked, from the memo — restated, not relitigated)

| Decision | Choice |
|---|---|
| Additivity | **Strictly additive.** Never remove, reorder, or normalize an existing manifest entry. The manifest is the source of truth; a host that disappeared from ssh config stays in the manifest (removal is `apply`/`prune` territory). |
| Server name clash, different host/port/user | **Manifest wins; skip the incoming entry; warn on stderr, and as a comment line in the merge-marker block when a block exists** (see *Nothing to merge* — idempotency adjudication). A silent overwrite could redirect a future `apply` at a different machine. |
| Known fingerprint under a different name | **Manifest owner wins; no new user; surfaced on stderr.** Turns a would-be `config.Parse` duplicate-fingerprint "bug:" abort into the correct semantic. Mirrors adopt's known-key path. |
| Same user name, different key | **Suffix the incoming name `-2`/`-3` + warn; never append the key to the existing user.** Loud over-splitting beats quiet identity merging (adopt's locked stance). |
| Overlapping access | **Append; the config layer's union semantics absorb it** — with the idempotency dedupe below so re-runs stay no-ops. |
| Server in a wildcard user's `except:` | **Never re-grant; warn; leave for audit.** Carried unchanged from adopt. |
| `--operator` key owned by an existing non-operator user | **Hard error.** Operator status protects keys from future revocation; promotion must be an explicit manifest edit. |
| Flag | `--merge FILE` (names the manifest to merge into; distinct role from `-o`). Not the default. |
| Output contract | Unchanged: stdout by default, `-o`/`--force` via atomic `writeFileNoClobber`. In-place is spelled explicitly: `--merge sshepherd.yaml -o sshepherd.yaml --force` (memo decision 6 — acceptable, and safe: FILE is fully read before the temp-file+rename write). |
| Marker | No stacked `# generated by…` headers. A dated `# merged by sshepherd import from <src> on <date>` comment rides the **first appended node**; conflict warnings ride the same block as `# WARNING:` lines. `<src>` is the ssh-config path as typed (never home-expanded — same leak rule as the regenerate header). Date injected at the cmd layer for testability. |
| Self-check | Merged output must pass `config.Parse` — enforced twice, as today: inside `manifest.Encode` and by the cmd's existing "bug:" gate. |
| Renderer | Slice 1's `internal/manifest` (strategy A, yaml.v3 node API), fidelity contract "comments preserved; blank lines and quote styles may normalize". |

## Decision 4 — adjudicated: **Option A**, extend access for already-known keys

When an identity-derived key's fingerprint already belongs to a manifest
user, `import --merge` extends that user's access to the covered servers
not already granted (adopt-style `Extension`). Rationale, over Option B
(net-new only): non-merge import emits these grants today, so merge
dropping them silently discards data import verifiably had; import is
**offline**, so it is the only way to express "grant my existing key to
this new machine before it is reachable" (adopt discovers *installed* keys
over SSH and cannot help there); and an appended server nobody is granted
would make a later `apply` write an `authorized_keys` without the
operator's key — a lockout built from a merge that looked successful.

Three guardrails, already implied by the locked rules: extensions are
deduplicated against existing grants **including wildcard coverage**, never
granted into an `except:` carve-out, and never created for operator owners
(their fleet-wide grant is implicit). Every extension is visible in the
appended block and the stderr summary.

## Deliberately deferred (NOT in this slice)

- Deletion/pruning of any manifest entry (`apply`/`prune` territory — never in

## Reconciliation semantics

Identity keys differ per section (the memo's core observation), and the
reconciler processes them in dependency order: servers first (grants reference
them), then users (grants reference them), then access.

### Servers — keyed by name

For each server-worthy converted host (`User` resolved — the existing
`serverWorthy` predicate and its skip warnings are unchanged):

- **Name absent from the manifest** → append `ServerEntry{Name, Host, Port, User}`
  (port omitted when effective 22, mirroring `serverOut`).
- **Name present, entry identical** — same `Host`, same `User`, same effective
  port (host `0`/`22` vs the manifest's validation-defaulted `22` compare
  equal; exact string compare on host and user, deliberately conservative) →
  **skip silently**, with a single debug-level note
  (`server "web-1" already in the manifest — identical, skipped`). Not a
  conflict, not a warning, no marker comment: this is the idempotent-re-run
  common case and must not accumulate noise. Manifest-only fields
  (`description`, `authorized_keys_file`) never participate in the compare —
  import cannot produce them, and their presence does not make the entries
  different machines.
- **Name present, any of host/port/user differs** → **conflict: manifest wins.**
  The incoming entry is dropped; one warning on stderr, plus a
  `# WARNING: server "web-1" in <src> differs from the manifest (host/port/user) — manifest kept`
  line in the marker block when one exists. **Derived rule:** any access
  grant referencing that alias is also dropped, with its own warning — the
  alias names a *different machine* in the manifest, and appending the grant
  would give the identity's key access to the manifest's machine, which the
  ssh config never said. Consistent with manifest-wins; audit/adopt remain
  the tools that reconcile the real machine later.

### Users — keyed by fingerprint, name is only a label

For each identity-derived user (single key each, by construction):

- **Fingerprint known, same name** → no new user; fall through to access.
  Combined with grant dedupe, an unchanged ssh config re-run is a clean
  no-op.
- **Fingerprint known, different name** → **manifest owner wins**: no new
  user; access handling proceeds against the *owner's* name. Surfacing rule
  (noise adjudication): this finding logs as a **warning only when it
  produces a plan change** (an appended extension); when the owner is
  already covered — the steady state after run 1 — it logs at **info**
  (`key SHA256:… from <src> belongs to manifest user "alice" — already
  covered`). A deterministic re-run must not warn forever.
- **Fingerprint unknown, name collides with a manifest user (or an
  already-claimed incoming name)** → suffix `-2`, `-3`, … + warn; the rename
  **cascades to that user's access entries**. Never append the key to the
  existing same-named user. **Bookkeeping (pinned):** the taken-name set is
  seeded with **all** manifest user names up front; incoming users claim
  sequentially in input order (so manifest `x` + incoming `x`, `x-2`
  resolves to `x-2`, `x-3` with no transient collision); and grants travel
  on the incoming user **struct**, never looked up by name — a name-keyed
  map would misattribute grants after a rename. (`identity.claimName` is
  unexported; the reconciler implements the same rule locally rather than
  reusing it across packages.)
- **Fingerprint unknown, name free** → append
  `UserEntry{Name, Description: "imported from <source> (…)", Comment, Operator, Keys}`
  exactly as non-merge import renders it.
- **Grantless-user rule (adjudicated):** a net-new user whose *entire*
  server list was dropped by the server-conflict rule is **not appended at
  all** — one warning names the cause
  (`user "web-x" not added: its only server "web-1" conflicts with the
  manifest`). Appending a key no server will ever receive is exactly the
  half-truth Option A's rationale condemns, and the self-check cannot catch
  it. A new user with a *partially* surviving list is appended with the
  surviving grants (the dropped pairs already warned).

### Access — append with idempotency dedupe

For each surviving (user, servers) pair, filter the server list down to pairs
not already covered. "Covered" for a possibly-new server name means, in order:

1. the owner is an **operator** → covered (implicit fleet-wide grant; never
   emit an extension for an operator — matches `DesiredFor`'s "operator wins
   unconditionally");
2. an explicit or expanded grant exists (`cfg` grants lookup) → covered;
3. the user has a **wildcard grant** and the server is **not** in its
   `except:` → covered — this is the *wildcard absorption* rule: a `"*"` user
   automatically gains every appended server, so extending them explicitly
   would be redundant clutter (and note 2 alone cannot see this, because the
   loaded config expanded `"*"` against the *old* fleet only);
4. the user has a wildcard grant and the server **is** in its `except:` →
   **not covered and never re-granted**: warn
   (`key of "alice" used for "db-1" in <src>, which her except: list deliberately excludes — not re-granted; audit flags this drift`)
   and drop the pair. Locked rule, identical to adopt's.

**Aggregation (adjudicated — adopt's precedent, `extByUser`):** extensions
for existing users are merged **per owning manifest user** — several
incoming keys owned by one user contribute to a single server set, deduped
— and emitted as **one access entry per owner**, in manifest `cfg.Users`
order, each entry's server list in first-touch order. New users' grants are
emitted per new user in input order. An entry whose server list filters to
empty is not appended. Existing access entries are never edited — a user's
new servers arrive as a *new* appended entry; the config layer's union
semantics make the duplication harmless and the diff reviewable.

### Wildcard compaction interaction

Non-merge import compacts a grant covering every emitted server (≥2) to
`["*"]`. Under `--merge` the fleet is **manifest servers ∪ appended servers**,
and compaction applies only to **net-new users**, only when their grant covers
that entire merged fleet (≥2 servers), with the same review warning. In
practice this almost never fires — a config-derived grant does not cover
manifest servers the ssh config never mentioned — and that conservatism is the
point: `"*"` opts a user into every *future* server, and in merge mode it
would additionally grant manifest machines import knows nothing about.
Extensions are never compacted, and existing access entries are never
rewritten to or from wildcard (strictly additive).

### Flag interactions

- **`--servers-only --merge FILE`** — reconcile servers only; no users or
  access appended (identity resolution skipped exactly as today). The
  existing `--operator`/`--servers-only` conflict error is unchanged.
- **`--operator k.pub --merge FILE`** — after `MarkOperators`, per marked key:
  fingerprint owned by an existing **non-operator** manifest user → **hard
  error, nothing written** (locked); owned by an existing **operator** user →
  covered, silent no-op (idempotent re-run of the same flag); unknown →
  appended as a new grantless operator user (fleet-wide grant implied, no
  access entry — as non-merge import renders it), name suffixed on collision.
- **FILE == `-o` target** — allowed with `--force` (memo decision 6):
  `import --merge sshepherd.yaml -o sshepherd.yaml --force`. Safe because
  FILE's bytes are fully read up front and the write is temp-file + rename;
  without `--force` the no-clobber link fails with the normal
  "already exists" error.
  Amended 2026-11 (P12): in-place `-o FILE --force` saves through
  `manifest.Store` (lock, changed-since-read refusal, mode/owner kept;
  identical bytes write nothing). The lock sidecar is opened no-follow and
  must be a regular file owned by the user or the manifest's owner; without
  `--force` the run is refused with `FILE is the manifest this run read;
  pass --force to update it in place`.
- **Nothing to merge (idempotency adjudication)** — an empty reconciliation
  returns the original bytes **byte-identical** and logs
  `nothing to merge: the manifest already covers <src>`; the summary line
  and marker are suppressed. This deliberately extends to **conflict-only
  runs**: when every incoming item is dropped by manifest-wins rules,
  nothing is appended, so no marker block exists and the file carries no
  `# WARNING:` lines — the warnings live on stderr (always emitted). The
  memo's "warn … + header comment" row is satisfied whenever a marker block
  exists; a warnings-only comment block was rejected because the conflict
  persists on every re-run and would break byte-identical idempotency
  forever. (Adjudicated 2026-07-19; implementers must not "fix" this back.)

## Per-package design

### `internal/config` — two exported queries (small)

- `func (c *Config) Covers(user, server string) bool` — reports whether the
  user's access (explicit grants, or wildcard minus `except:`) covers
  `server`, where `server` need not exist in the manifest yet (wildcard covers
  future servers by design). Backed by the existing `grants` map plus a
  wildcard/except scan of `c.Access`. Doc comment must state: **operators'
  implicit fleet-wide grant is deliberately excluded — check `Operator`
  first** (otherwise a future caller reads `Covers(op, srv) == false` as "no
  access", contradicting `DesiredFor`).
- `func (c *Config) ExceptCarveOut(user, server string) bool` — adopt's
  `hasExceptCarveOut`, moved here verbatim with its caveat comment (only
  meaningful for pairs the grant union does not cover); `internal/adopt`
  refactors to call it. Reconcile calls it only after `Covers` returned false,
  satisfying the caveat.

### `internal/manifest` — expose the servers append

The slice-1 spec anticipated this exactly: *"a servers append later is
trivial; not exposed now — nothing uses it."* Now something uses it. The
change is mechanical because `appendToSection` is already section-agnostic
(keyed by name, handles missing/null/flow-empty shapes):

- New `type ServerEntry struct { Name, Host string; Port int; User string }` —
  the fields import can produce; `Port` omitted when 0 (caller passes 0 for
  effective 22, mirroring `serverOut`'s omitempty). No `Description`/
  `AuthorizedKeysFile` until a caller exists.
- New `serverNode(ServerEntry) *yaml.Node` in the generators' field order
  (name, host, port, user).
- `Append` grows a servers parameter:
  `Append(comments []string, users []UserEntry, servers []ServerEntry, access []AccessEntry) error`,
  routing through `appendToSection("servers", …)` between users and access.
  The marker-placement priority becomes first user, else **first server**,
  else first access entry. Breaking signature; one **production** caller
  (`adopt.go` passes `nil` — a one-line change landing in the same commit)
  plus the package's own test and fuzz callers, updated in the same commit.

Load, Encode, the shape checks, and the fidelity contract are untouched.

### `internal/reconcile` — new pure package

Mirrors `internal/adopt`'s shape: pure logic, no I/O, cmd layer owns rendering.

```go
// Input: the loaded manifest's *config.Config, the server-worthy converted
// hosts, and the identity-derived users (nil under --servers-only).
func Build(cfg *config.Config, hosts []sshcfg.Host, users []identity.User) (Plan, error)

type Plan struct {
    NewServers []ServerAdd   // Name, Host, Port, User
    NewUsers   []UserAdd     // Name (post-suffix), Description, Comment, Operator, Keys
    Extensions []Extension   // User, Servers — one per owning user, cfg.Users order
    NewGrants  []Grant       // new users' grants, post-rename, post-compaction (Servers may be ["*"])
    Warnings   []string      // every conflict/skip/carve-out, marker-comment-ready
    Notes      []string      // info-level findings (steady-state "already covered" etc.)
}
```

`Extension` reuses adopt's shape (same two fields, same semantics, same
rendering into `manifest.AccessEntry`) but is declared locally — importing
`internal/adopt` for a two-field struct would couple two peer command
packages for nothing. The only `error` return is the locked `--operator`
promotion conflict (hard error, nothing written); everything else is a
warning or note in the plan. `Build` is deterministic: hosts and users are
processed in input order, warnings in discovery order, extensions in
`cfg.Users` order.

### `cmd/sshepherd/import.go`

- `--merge FILE` (string flag). When set: read FILE's bytes once,
  `manifest.Load` them (validation + node tree + `Config()` in one step,
  surfacing `cfg.Warnings` like adopt does), run the *unchanged* convert
  pipeline (`sshcfg.Load`, `serverWorthy` filter, `resolveUsers`), then
  `reconcile.Build` instead of `generateManifest`.
- `renderMergedImport(mf, raw, plan, src, date)` — the analogue of adopt's
  `renderMergedManifest`: empty plan → `raw` byte-identical; otherwise the
  marker `merged by sshepherd import from <src> on <date>` plus the plan's
  warnings as `WARNING:` comment lines, then
  `mf.Append(comments, users, servers, access)` + `mf.Encode()`. `date` is a
  parameter; `time.Now().Format("2006-01-02")` is applied only in `RunE`, so
  goldens inject a fixed date.
- Warnings → stderr WARN; notes → stderr info. Summary at info level:
  `merged: +1 server, +2 users, +1 extension, +2 access entries, 1 conflict skipped`.
- Everything downstream is untouched: the "bug:" `config.Parse` gate, stdout
  default, `writeFileNoClobber` with `-o`/`--force`.

## Testing

Strict TDD order throughout: each behavior gets a failing test before its
implementation (project policy).

- **Unit, `internal/config`** — table-driven: `Covers` across explicit /
  wildcard / except / unknown-user / not-yet-existing-server / operator
  (excluded by contract) cases; `ExceptCarveOut` tables move with the
  function (adopt's existing coverage keeps passing through the refactor).
- **Unit, `internal/manifest`** — servers append: into an existing block
  section, flow-empty `servers: []`, null, and missing sections; marker rides
  the first server when the plan is servers-only; field order and port
  omission match the generators; `Append(nil-users, servers, nil-access)`
  from a servers-only plan.
- **Unit, `internal/reconcile`** — one table per conflict rule (the binding
  memo table, row by row), plus: identical-server silent skip;
  conflicted-server grant drop; grantless-user skip (all servers
  conflicted) vs partial survival; same-name-same-fingerprint idempotent
  no-op (empty plan); conflict-only run → empty plan; rename cascade into
  grants incl. the seeded-set case (manifest `x`; incoming `x`, `x-2` →
  `x-2`, `x-3` with correct grant attribution); multi-key-owner extension
  aggregation (two incoming keys of one owner, overlapping server lists →
  one merged entry, `cfg.Users` order); wildcard absorption (wildcard user
  + new server → no extension); except carve-out never re-granted; operator
  owner → no extension; `--operator` promotion → error; merged-fleet
  wildcard compaction (fires only on full coverage, never for extensions);
  warning-vs-note classification; determinism.
- **Golden, cmd level** — injected fixed date, commented manifest fixture:
  full merge (new server + new user + extension + conflict warning — original
  comments intact, no regenerated header, marker + WARNING lines on the first
  appended node); servers-only merge; idempotent re-run byte-identical;
  conflict-only run byte-identical with stderr warnings; in-place
  `--merge X -o X --force`.
- **Fuzz** — **extend `FuzzMergeRoundTrip`; no new target.** Rationale: the
  project rule fuzzes parsers, and this slice adds no parser — `reconcile` is
  pure logic over inputs from two already-fuzzed parsers (`internal/sshcfg`'s
  existing target and `manifest.Load`). What *is* new encode surface is the
  servers append path, so the existing target's mutation pass grows a fixed
  `ServerEntry` (+ a grant to it) alongside its fixed user, asserting the
  originals and both additions survive re-parse — **with a third skip-guard
  mirroring the existing two: inputs already claiming the fixed server name
  (or an incompatible shape for the fixed grant) are skipped, so the
  harness never fabricates a duplicate-server "crash".** Same invariant,
  same seed corpus — a separate target would duplicate both.
- **Suite-wide** — goleak `TestMain` in `internal/reconcile` (the only new
  test package), `-race`, coverage `≥80%` gate via `make coverage`, all under
  the single `make check`.
