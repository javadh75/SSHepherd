# Design: `adopt --merge` — comment-preserving manifest append (merge slice 1)

- **Date:** 2026-07-16
- **Status:** Implemented (2026-07-16)
- **Amended by:** [`revoke` / `rotate`](2026-10-23-revoke-rotate-design.md) (2026-10-23) — `internal/manifest` also removes and replaces entries; Load's rejection texts are command-neutral.
- **Prior art:** `docs/superpowers/specs/2026-07-16-manifest-merge-memo.md`
  (the decided memo this slice executes),
  `docs/superpowers/specs/2026-07-10-adopt-fleet-discovery-design.md`
  (deferred exactly this: "In-place manifest merging or comment-preserving
  YAML round-trip").
- **Scope:** New package `internal/manifest`; a `--merge` flag on `adopt`
  (`cmd/sshepherd/adopt.go`). `internal/adopt.Build` unchanged.

## Context & goal

Adopt already has merge *semantics* — it attributes every installed key
against the loaded manifest and emits existing sections plus additions — but
its rendering is a regeneration: everything `config.Parse` discards
(comments, blank lines, ordering nuances) is lost. Once the manifest is a
hand-maintained, commented file, that loss makes re-running adopt
destructive to review history. `--merge` changes only the rendering: keep
the operator's text, append what the plan adds.

## Decisions (locked, from the memo)

| Decision | Choice |
|---|---|
| Strategy | **A: yaml.v3 node API** — decode to `*yaml.Node`, surgically append to the section sequences, re-encode the document. |
| Fidelity contract | **"comments preserved; blank lines and quote styles may normalize."** |
| Scope | Adopt-only. No import reconciliation, no deletion, no reordering/normalizing of existing entries, no heuristic identity merging. |
| Flag | `--merge` (bool) — adopt's manifest is already `--config`, so no second path is needed. Not the default. |
| Output contract | Unchanged: stdout by default, `-o`/`--force` via the atomic `writeFileNoClobber`. In-place is spelled explicitly: `--merge -o <same file> --force`. |
| Header | No stacked `# generated by…` header. A dated `# merged by sshepherd adopt on <date>` comment rides the **first appended node**, with one `# WARNING: server X unreadable…` line per unreadable server (`--partial`), so history accretes where the additions live. |
| Self-check | Merged output must pass `config.Parse` (both inside `manifest.Encode` and via the cmd's existing "bug:" gate). |
| yaml.v3 dependence | Stay on `gopkg.in/yaml.v3`; re-evaluate goccy/go-yaml only if a node-API defect actually bites. |

## `internal/manifest`

- `Load(data)` decodes the bytes twice: `config.Parse` for validation (Load
  rejects what config.Parse rejects; callers get `Config()` with `OwnerOf`
  for free) and a `yaml.Node` tree for the eventual re-encode.
- **Load is stricter than config.Parse** where the struct decoder tolerates
  node shapes that break the re-encode → re-parse self-check (all found by
  fuzzing): top-level keys must be plain `users`/`servers`/`access` scalars,
  every mapping key anywhere must be a plain non-empty scalar (an anchored
  empty key decodes as skippable but re-encodes into a key the reparse
  rejects), and null sequence items are rejected (silently skipped when
  decoding into a slice, materialized as `""` by the re-encode). Invariant:
  anything Load accepts is structurally re-encodable.
- `Append(comments, users, access)` appends `UserEntry`/`AccessEntry` nodes
  to their section sequences through a shared `appendToSection` helper (a
  servers append later is trivial; not exposed now — nothing uses it).
  Handled shapes: flow-style empty section (`users: []`, our generators'
  bootstrap output) converts to block style; a null section (`users:`)
  rebuilds as a sequence; a missing section is created at the end. The
  comment lines land on the first appended node (first user, else first
  access entry). Appending nothing is a no-op.
- `Encode()` re-encodes with 2-space indent and self-checks the result
  through `config.Parse`, failing `bug:`-loudly rather than emitting a
  manifest our own loader rejects.

## `adopt --merge`

- `--merge` reads the manifest bytes once, builds the config through
  `manifest.Load`, and runs the unchanged pipeline (`readFleet`,
  `adopt.Build`, strict/`--partial` gate).
- Rendering goes through `renderMergedManifest`: empty plan → the original
  bytes, **byte-identical** (and the nothing-to-adopt note, never the
  "adopting" summary); otherwise plan additions append in the regenerate
  path's order (new users; extensions, then new-user grants). The date is a
  parameter — `time.Now()` is applied at the cmd layer only, so tests and
  goldens inject a fixed date.
- stdout/`-o`/`--force` behavior is identical to regenerate mode.

## Deliberately deferred (NOT in this slice)

- **Slice 2 — `import --merge FILE`:** reconciliation (fingerprint dedupe,
  manifest-wins server conflicts, name suffixing, `--operator` promotion
  rules) reusing this renderer.
- Deletion/pruning of any manifest entry (`apply`/`prune` territory).
- Byte-perfect fidelity (strategy C text-splice) — buildable later behind
  the same interface if the fidelity contract proves insufficient.
- Heuristic user identity merging (still deferred, per the adopt spec).

## Testing

- **Golden (`internal/manifest`)** — commented fixture (head, between-entry,
  inline, and foot comments plus a blank line): comments survive the append;
  the blank-line loss is visible in the golden per the fidelity contract.
- **Unit** — Load rejects what config.Parse rejects plus the fuzz-found
  shapes; section shapes table (flow-empty `[]`, null, missing); merge
  marker rides the first appended node (access-only plans included); empty
  append is a no-op; pure load/encode round-trip.
- **Fuzz** — `FuzzMergeRoundTrip` (project rule: a merge round-trip is a
  parser): for arbitrary bytes, if Load accepts, an append-nothing Encode
  must reparse with every user name, server name, and access pair intact.
  Seeded with the commented fixture, flow-empty manifests, and the three
  fuzz-found crashers; wired into `make fuzz`.
- **cmd goldens/tests** — merged output with a fixed injected date (original
  comments survive, no regenerated header, same desired sets as the
  regenerate-mode golden); `--merge` with nothing to adopt is byte-identical
  and keeps the logging contract. No-clobber/`--force` already covered.
- Suite-wide: goleak `TestMain` in `internal/manifest`, `-race`, coverage
  gate as usual.
